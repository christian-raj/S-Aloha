## Mise à niveau des bibliothèques : .NET 10 (LTS), React 19

- **Quoi** : API de `net8.0` à `net10.0` (le projet de tests y était déjà) ; EF Core,
  EF Core Design et JwtBearer 10.0.13, Npgsql EF 10.0.3, Swashbuckle 10.3 (OpenAPI 3),
  Novell.Directory.Ldap 4.0 ; Microsoft.AspNetCore.Mvc.Testing 10.0.13, Microsoft.NET.Test.Sdk
  18.11 ; images `sdk:10.0` et `aspnet:10.0` ; CI sur le seul SDK 10 ; `dotnet-ef` 10. Frontend :
  React et React DOM 19.3, Vite 8.3, @vitejs/plugin-react 6.1, Vitest 5.0, jsdom 30.1.3.
- **Pourquoi .NET 10 et pas 11** : .NET 11 et Npgsql 11 ne sont publiés qu'en version
  candidate (RC2 et RC1) ; .NET 10 est la version LTS stable. Passage à .NET 11 à sa sortie.
- **Adaptations** : `LdapService` porté sur l'API asynchrone du client LDAP 4 (connexion,
  liaison, recherche ; `AuthenticateAsync`, `SearchAsync`, `FindAsync`) et appelants
  (connexion, annuaire, INC-13). `DatabaseSchema` : avec EF Core 10,
  `IHistoryRepository.Exists()` répondait vrai sans table d'historique, et `EnsureCreated`
  peut laisser un historique vide — la base créée avant les migrations est désormais reconnue
  par une vérification SQL de la table et un historique vide (le test de mise à niveau échouait
  sur « relation "Problems" already exists »). Nouveau test : la description OpenAPI est servie.
- **Sur l'AMD** : connexions des trois comptes de démo, mauvais mot de passe (401), recherche
  dans l'annuaire Samba et INC-13 validés avec le client LDAP 4 ; aucune migration appliquée au
  démarrage ; OpenAPI 3.0.4. `ENV ASPNETCORE_URLS` retiré du Dockerfile : l'image aspnet:10.0 écoute
  déjà sur 8080 (`HTTP_PORTS`), la double définition faisait journaliser un avertissement.
- **Contrôles** : 188 tests d'API, 87 tests d'interface, build ; `dotnet list package
  --vulnerable` et `npm audit` : 0 vulnérabilité ; aucun paquet NuGet en retard.
- **Fichiers** : `SAloha.Api.csproj`, `SAloha.Api.Tests.csproj`, `backend/Dockerfile`, `ci.yml`,
