## Étape 6 du lot 1 — Périmètres : liens, console, reporting, recherche

- **Quoi** : PER-08 — un lien vers un enregistrement d'un autre périmètre reste listé mais
  masqué (« Enregistrement d'un autre périmètre », sans référence, sans lien, sans retrait) ;
  relier vers un enregistrement invisible répond comme une référence inconnue ; lire les liens
  d'un enregistrement invisible répond 404. PER-09 — la console se limite aux périmètres de
  l'utilisateur, ses blocs de pilotage aux périmètres dont il est gestionnaire (un User AD
  Manager d'un périmètre y a accès) ; le reporting (tableau de bord et synthèse historique)
  porte sur ses périmètres ; la recherche et les cas similaires ne renvoient que des
  enregistrements visibles (filtre après classement, sur trois fois plus de candidats). Filtre
  « Périmètre » dans la console et le reporting dès que l'on a plusieurs périmètres ; l'Admin
  voit tout et peut filtrer.
- **Pourquoi** : sans ces vues, la portée par périmètre (PER-03 à PER-07) se contournait par
  la console, le reporting, la recherche ou l'onglet Liens.
- **Fichiers** : `ItemLink.cs` (`LinkTarget.PerimeterId`, `Shared`), `LinksController.cs`,
  `SearchController.cs`, `ConsoleController.cs`, `DashboardController.cs`,
  `ReportsController.cs`, `ReportScope.cs` (nouveau), `PerimeterAccess.cs` ; frontend
  `LinkedItems.jsx`, `Console.jsx`, `Reporting.jsx`, `api.js`, `styles.css` ; tests
  `PerimeterViewsTests.cs` (125 tests d'API).
- **Documentation** : périmètres (PER-08, PER-09), reporting (filtre), recherche (RAG-13),
  architecture, frontend, plan d'implémentation, `CHANGELOG.md`.
- **Reste pour l'étape 6** : écran Administration › Périmètres.
- **Commit** : branche `lot1-etape6-perimetres-vues`.

## Conformité NIS 2 : version du référentiel figée (NIS-18)

- **Quoi** : `Assessments.ReferentialVersion` (version évaluée) et
  `Assessments.FrozenRequirementsJson` (exigences applicables figées à la validation : code,
  objectif, pilier, thématique). Questionnaire, score et synthèse du reporting (REP-40)
  lisent les exigences figées d'une évaluation validée ; la réouverture les libère et
  réaligne la version. Au démarrage, les évaluations validées antérieures sont figées
  **avant** l'alignement de la structure embarquée. Migration `AssessmentReferentialVersion`
  (les évaluations existantes reçoivent ReCyF v2.5).
- **Pourquoi** : dernière règle du lot 1 réalisable sans données de l'organisation (RAG-10
  attend un jeu de requêtes réelles) ; une nouvelle version du ReCyF (le texte actuel est une
  « version de travail ») aurait modifié le score d'évaluations déjà validées.
- **Fichiers** : `AssessmentReferential.cs` (nouveau), `Entities.cs` et
  `AssessmentsController.cs` (conformité), `DashboardController.cs`, `Program.cs`,
  migration ; tests `ReferentialVersionTests.cs` (127 tests d'API), accès direct à la base
  dans `ApiFixture`.
- **Documentation** : conformité NIS 2 (NIS-18), base de données, reporting (REP-40), plan
  d'implémentation et plan d'action (reste du lot 1 : RAG-10), `CHANGELOG.md`.
- **Commit** : branche `nis-18-version-referentiel`.

## Commentaires (SOC-24)

- **Quoi** : table `Comments` (cible type et identifiant, comme un lien), API
  `/api/comments`, onglet « Commentaires » sur toutes les fiches (problèmes compris), entre
  Liens et Historique. Commentaire public ou note de travail ; la note se lit et s'écrit
  par quiconque voit l'enregistrement dans ses périmètres, sauf le côté demandeur (déclarant,
  bénéficiaire d'une demande) qui n'est ni responsable ni gestionnaire du périmètre ; retrait
  par l'auteur ou un Admin ; les commentaires partent avec leur enregistrement.
- **Décision prise** : la règle ne disait pas qui forme « l'équipe IT » ; la lecture retenue
  (le demandeur non intervenant ne voit pas les notes) est écrite dans SOC-24, à amender si
  besoin.
- **Pourquoi** : premier des deux prérequis communs restants de la sortie du MVP.
- **Fichiers** : `backend/Core/Comments/` (nouveau), `ItemLink.cs` (`ItemLinks.Records`),
  `AppDbContext.cs`, `RecordController.cs`, migration `Comments` ; frontend `Comments.jsx`,
  `RecordDetail.jsx`, `ProblemDetail.jsx`, `api.js`, `styles.css` ; tests
  `CommentsTests.cs` (130 tests d'API), `Comments.test.jsx` (62 tests d'interface).
- **Documentation** : règles métier (SOC-24), frontend, architecture, base de données, plan
  d'action (prérequis de sortie du MVP), `CHANGELOG.md`.
- **Commit** : branche `soc-24-commentaires`.
